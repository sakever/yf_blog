现在接触一个新技术，写一个新项目，都是交给 AI 做，甚至现在写文章都没啥价值了，有啥问题问问 AI，什么都能处理，我昨天接手了一个前端工程，一行代码没写把需求做出来了

所以昨天我问 AI 了一个问题，问在这个时代，学习前端还有必要吗，回复如下：

AI 把“实现”的成本降到了接近零，于是瓶颈转移到了：定义需求、提供上下文、验收结果。 这三件事的水平，恰恰取决于你对系统的理解程度

学什么（按性价比排序）

概念和结构，不是语法——花一周了解 React/Next.js 的心智模型：页面=组件树、状态驱动渲染、数据从 API 到页面的流向。目标不是写，是看懂 AI 改了哪些文件、为什么这么组织

阅读能力——能读懂 TypeScript/React 代码的逻辑部分（不用管样式细节），能 review AI 的 diff，能发现“它改了不该改的东西”

调试与验收工具——浏览器 DevTools（Network 看请求对不对、Console 看报错）、看服务端日志

你产品的领域知识——API 契约、鉴权链路、数据流转。这是你相对 AI 的真正优势所在
不用学的：CSS 细节、组件库 API、构建配置……这些 AI 比人熟练，且随时可查。

一句话版本

你已经是后端程序员，学前端的边际成本很低、回报很高——不是为了写，而是为了让“指挥 AI”和“验收 AI”这两件事从碰运气变成有把握。 会提问、能看懂、可验证的人，用 AI 的效率是完全不懂的人的很多倍。这次会话里你贴 DTO、给类型码的沟通方式，就是这个效率的体现

总结来说是：会提问、能看懂、可验证。用 AI 写代码是一个黑盒逻辑，现在学代码就是把黑盒变成白盒，但是我现在不觉得把一堆看不懂的代码变成白盒有什么收益，除非项目十分庞大。就算项目十分庞大，维护优秀的 claude.md 也比之前一遍遍调试、读项目要来的轻松

但是我还是跟着建议将项目大致看了一遍，重点不在于看语法、用了什么库、甚至项目结构，而是学习了解一些基础中的基础
## 路由

路由管页面怎么组织、URL 怎么映射、用户怎么跳转。Next.js 没有路由配置文件，文件夹结构就是 URL：
```
src/app/(dashboard)/videos/ugc-scene/page.tsx   →  URL: /videos/ugc-scene
src/app/login/page.tsx                          →  URL: /login
```
两个特殊语法：
```
(dashboard) 带括号 = 路由组，只共享布局，不占 URL 段
_components 下划线开头 = 私有文件夹，不参与路由，纯放组件
```
布局什么的可以共享，侧边栏、导航栏、Dashboard 外壳可以放在 layout 里，子页面切换时不用重复渲染和重复写代码

## 渲染策略有啥用
渲染策略决定页面 HTML 是在浏览器里生成，还是在服务器/构建时生成，以及什么时候生成。常见有：

策略	在哪生成	适合场景	主要好处
CSR 客户端渲染	浏览器	后台仪表盘、登录后页面	交互强、服务器压力小
SSR 服务端渲染	每次请求时服务器	个性化页面、实时数据	首屏快、SEO 好、数据较新
SSG 静态生成	构建时	博客、文档、营销页	极快、便宜、易缓存
ISR 增量静态再生	构建后按需/定时再生成	电商列表、内容站	静态速度 + 数据可更新

降低服务器成本和提升缓存效率，SSG 可以 CDN 缓存，成本低、速度快。SSR 灵活但服务器成本更高。ISR 是折中：大多数请求拿静态缓存，过期后后台再生成

按页面选策略：

- 首页/博客：SSG 或 ISR
- 商品详情：ISR/SSR
- 后台管理：CSR
- 登录后个性化：SSR 或 CSR

渲染策略解决的是用户多快看到内容、搜索引擎能不能抓到、数据够不够新、服务器成本高不高的权衡问题

## 前端项目编写流程

一、做前端项目或者接手项目前先看一下该项目用了什么框架和库，了解一下项目大概的代码流程

以 React 举例，React 的世界只有一条公式：页面长什么样，完全由状态计算出来。状态变 → 页面自动重渲染，你永远不需要手写刷新逻辑

拿举报筛选举例（page.tsx）：
```
你选「有举报」 → setReportedFilter(true)      // 改状态
  → hook 里的 listQueryParams 变化            // 状态的连锁反应
  → useQuery 的 queryKey 变化                 // 缓存 key 变了
  → 自动重新 POST /ugcscene/getAll            // 带上 reported: true
  → data 变化 → 表格自动重新渲染
```
整条链没有任何一步手动调用刷新。读 React 代码的方法：先找 state，再找谁改 state，渲染自然会跟着对

二、整理需求文档给 AI。前端代码推荐先按个 taste-skill
```
npx skills add https://github.com/Leonxlnx/taste-skill
```
三、看报错：页面报错都在 Console 面板

报错第一行是错误摘要（如 Uncaught TypeError: Cannot read properties of null），下面展开是调用栈，点击栈里的文件名会直接跳到出错的那行代码

Network 里的 CORS 报错也只在 Console 显示（blocked by CORS policy）

页面不对劲时，先开 Console 看有没有红字，再开 Network 看请求。你甚至不需要了解问题是什么，AI 会解决，你只需要发现问题
